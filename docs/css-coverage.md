## Drift classification — accidental vs. deliberate

Manual read of each of the 41 Drifted rules against `app/globals.css`'s own inline comments and the surrounding component code. Not auto-generated (this is judgment, not a mechanical diff) — reported before anything is changed, per instruction.

**Deliberate — no restoration planned:**

- **`body`** (`font-family: var(--font-inter)` vs literal `Inter`) — forced by `next/font`; there is no way to write the literal family name and still get `next/font`'s optimisation. Not a simplification, a tooling requirement.
- **`.awaiting`, `.brief`, `.replybox`** (missing `display:none`) — the prototype hides these with a CSS class toggle (`.awaiting.on`, `.brief.open`); the app hides them by not mounting the component at all. Different, equally valid mechanism for the same outcome. `.brief` itself deliberately keeps its own `.open`/`.bf-b` toggle for the *expand/collapse* behaviour, which is orthogonal to this.
- **`.bf-h`** (extra `border:none;width:100%;text-align:left`) — this is a real `<button>` element (correct, for accessibility) where the prototype's is a plain clickable `<div>`; the extra rules are a browser button-default reset, not scope creep.
- **`.modal-h b`** (extra `flex:1`) — needed to push the close button to the header's right edge in a flex row. (Its `font-size: 14px` vs the prototype's `15px` is a separate, accidental slip — see below.)
- **`.pk2 .pn` / `.field input`** (extra `font-size`/`white-space`/`overflow`/`text-overflow` truncation rules) — sensible handling for real dynamic names/values the static prototype's fixed demo strings never needed to truncate. Additive, not a regression.
- **`.browser` / `.phone`** (extra base `display:none`/`display:block`) — part of the same `.phonewrap` mechanism difference below, not an independent slip. See Phase 2 disposition.

**Accidental — restoring in Phase 2 step (d):**

- **`.cmts-h` / `.stage-h`** — missing the `background:transparent` override the prototype's rule ends on (both rules are `background:var(--surface)` then immediately `background:transparent` — the app kept only the first).
- **`.cmt`** — missing `transition:border-color .12s,box-shadow .12s`, `cursor:pointer`, `position:relative` (the last one matters: `.cmt.act`/`.cmt-anchor-target.act` and the card's own absolutely-positioned timestamp depend on it).
- **`.cmt-h`** — missing `padding-right:76px` (clears space for the absolutely-positioned timestamp).
- **`.cmt-h time`** — wrong mechanism, not just a missing value: prototype pins it with `position:absolute;top/right:var(--d-cmt)`; the app pushes it right with `margin-left:auto` instead. Looks similar at rest, moves differently as the card's content wraps.
- **`.quoted`** — `margin:5px 0` vs the app's `margin:0 0 7px`.
- **`.composer`** — missing `position:relative` (harmless today, but it's what `.anchorbar`/`.mentions` — both currently unbuilt — will need to position against once they exist).
- **`.intog`** — missing `padding:4px 8px;border-radius:var(--r);border:1px solid transparent` (the toggle currently has no hit-box padding or hover shape).
- **`.tog`** — missing `margin-left:auto`.
- **`.m-top`** — `padding:20px 16px 11px` vs the prototype's `34px 16px 11px`.
- **`.m-bar`** — `padding:12px 16px 22px` vs `12px 16px 26px`.
- **`.pk2`** — `padding:8px 10px` vs `6px 10px`.
- **`.srow`** — `padding:11px 0` vs `var(--d-set-y) 15px` (also drops the density token entirely).
- **`.modal`** — `max-height:80vh` vs `88vh`.
- **`.modal-h`** — `padding:13px 16px` vs `15px 20px`; also restoring `.modal-h b`'s `font-size:15px` (currently `14px`) alongside its deliberate `flex:1`.
- **`.modal-b`** — `padding:16px` vs `20px`.
- **`.field` / `.field input` / `.field textarea` / `.field select`** — not a simple value slip. `globals.css` defines **two unrelated rules under the same name**: a login-page-specific `.field{display:flex;flex-direction:column;gap:5px;font-size:13px;font-weight:500}` (Login section) and the prototype's own generic modal `.field{margin-bottom:16px}` + `.field input,.field textarea,.field select{...}` (Share modal section, added later). Because both are bare `.field`, CSS cascades them together on *every* `.field` in the app regardless of which one a component meant: the login form silently inherits `margin-bottom:16px` from the modal rule, and — more consequentially — the login page's inputs (`.field input`), which were written to be `font-size:13.5px;padding:8px 10px;background:var(--surface)`, get silently overridden to the generic modal's `font-size:13px;padding:7px 9px` by the same-specificity, later-in-file rule. The login page has been rendering with the wrong input styling since whichever phase added the generic modal `.field` rule. Fixing this needs a rename (e.g. `.authfield`), not a value restore — see Phase 2 step (d).
- **`.vsel select`** — currently re-declares `border`/`font`/`background-color` from scratch because bare `select` doesn't exist yet in the app. Resolves as a side effect of step (b); the leftover duplication gets trimmed there, not here.
