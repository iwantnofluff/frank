# Note for Phase 5 — baseline schema reconstruction

`supabase/migrations/` only goes back to `phase6_shared_links.sql` — that part of `frank-conventions` is still accurate. But `supabase/seed.sql` is not just a fresh-install seed script: reading it while chasing the comment-visibility question (`docs/comment-visibility-verification.md`) turned up the full table definitions, RLS policies, helper functions (`current_agency_ids()`, `is_agency_staff()`, `is_agency_admin()`, `current_client_ids()`), and triggers (`set_agency_id_from_*`, `comments_enforce_visibility`, `prevent_delivery_change_with_creatives`, `check_comment_reply_depth`, and others) — the same shape of thing Phase 5 was scoped to reconstruct from live-schema introspection because no migration file was assumed to exist for it.

Whether `seed.sql` is a *complete* and *current* record of phases 1-5 — versus a snapshot that's since drifted from what's actually live, or one that was itself never fully complete — hasn't been established. Only that it exists and covers substantially more ground than "no record at all." That's worth knowing now; verifying it is Phase 5's job, not this note's.

When Phase 5 is picked up: start by diffing `seed.sql` against the live schema (via the Supabase MCP server, read-only, as originally planned), rather than reconstructing `phase0_baseline.sql` from introspection alone as if nothing existed. Introspection becomes the tool for finding *drift between seed.sql and live*, not the sole source of truth from scratch. Flag explicitly anything `seed.sql` gets wrong or misses, per the original guardrail — this note is not a substitute for that comparison, just a pointer to do it starting from a better position than assumed.
